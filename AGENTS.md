# Project Instructions

## Specification

- Follow the specification explicitly referenced in the task.
- Do not introduce requirements absent from the active specification.
- Consult official documentation, language standards, and
  other reliable technical sources whenever useful.
- Report ambiguities and contradictions instead of silently
  resolving them.

## Development

- Prefer simple and maintainable solutions.
- Respect all dependency restrictions.
- Add appropriate automated tests.
- Run relevant tests before reporting completion.
- Do not weaken tests to make them pass.
- Do not modify unrelated project components.

## Workflow

- Discuss the implementation plan before starting development.
- Record approved plans and important architectural decisions.
- Verify the implementation against the specification.
- Report completed work, test results, and remaining limitations.

## Git

- The user owns Git history and commit decisions.
- Preserve existing history.
- Do not push changes without explicit approval.
- Do not commit secrets or generated build artifacts.
